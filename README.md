# מהמפץ הגדול לחיים ולאבולוציה · cosmos-to-life

אתר לימוד כרונולוגי בעברית: מן המפץ הגדול, אנרגיה וחום, חלקיקים, אטומים וכוכבים, דרך כימיה והיווצרות כדור הארץ, ועד מקור החיים, אבולוציה והתפתחות האדם.

**אתר חי:** https://cosmos-to-life.vercel.app/

**דיבוב עברי אישי (גרסת שימוש 1.0):** קישור בראש שני חלקי האתר ל־`dub.html`. עובד דרך שיתוף שמע של לשונית נפרדת ו־Gemini Live Translate עם מפתח API פרטי שמוזן בדפדפן, בלי לשמור אותו או לשנות סרטונים קיימים. מוגבל ל־10 דקות בהפעלה. ממשק וסימולציה נבדקו; דיבוב אמיתי עדיין דורש בדיקת משתמש ומפתח פרטי (לא לטעון שהניגון נבדק).
- **חלק א׳:** `index.html` — 6 פרקים, 210 יחידות לימוד.
- **חלק ב׳:** `life.html` — 2 פרקים, 184 יחידות לימוד.
- **סה״כ נכון ל-10 באוקטובר 2026:** 394 יחידות, 336 הפניות YouTube ייחודיות ועוד 58 מקורות נוספים (וידאו ישיר, Vimeo ו-PBS).

## אפשרות חינמית לדיבוב עברי — ללא API אישי
- בדף `dub.html` מופיע קודם מסלול **YouTube**: רצועת שמע עברית מובנית (אם קיימת), אחרת קישור להתקנת **AutoDub** מ-Chrome Web Store, ותחת כל וידאו של YouTube מוצג קישור ישיר לדף `youtube.com/watch?v=...`.
- לפי מפתח AutoDub, השירות ללא הרשמה, ללא מפתח API אישי וללא הגבלה יומית; הדבר לא נבדק בסשן האזנה ואינו התחייבות מצד הפרויקט. התוסף עובד באתר YouTube עצמו ולא בהכרח בנגן iframe שלנו. נדרשת רצועת כתוביות. ספק השירות מעבד מזהה סרטון וכתוביות.
- Google Live הקיים נשאר במקומו למקורות אחרים: ההגבלה שלנו ל-10 דקות להפעלה אינה מכסה חינמית כוללת; Google מתעדת גם מגבלת 15 דקות לסשן שמע רציף ללא דחיסה, ויש מגבלות שימוש חשבוניות נפרדות.
- אין לשנות את סדר 336 הסרטונים, את Auto-Next, את חלוקת שש היחידות לדף, או את נגני ההטמעה כשמשפרים דיבוב חינמי.

## עקרונות המשך לפרויקט
1. **קודם כול תקינות ניגון:** כל פריט צריך להציע צפייה *מתוך האתר*. השתמשו בנגן וידאו מקורי לקובץ רשמי כשאפשר, ב-YouTube/Vimeo/PBS המוצגים באתר כשצריך, ורק כמוצא אחרון בקישור חיצוני. אין לטעון שכל הפריטים עובדים ללא בדיקת ניגון בפועל.
2. **סדר פדגוגי רציף:** לשלב סרטונים חדשים במיקום הכרונולוגי/המושגי הנכון; לא רק להוסיף בסוף. לכל פריט הסבר ״למה עכשיו״ ושאלות מנחות. להתחיל בהסבר פשוט וויזואלי, להעמיק בהדרגה, ולסמן ספקולציה מול ידע מבוסס.
3. **חיפוש רחב ואיכותי:** לחפש גם סרטונים מתאימים מקורסים או ערוצים שכבר נכנסו לאתר — בלי להסתפק רק בערוץ אחד. עדיפות לסרטונים בהירים ומבוססים בעברית/אנגלית; שפה אחרת אפשרית כשהאיכות מצדיקה.
4. **מינימום עומס:** לשמור על ניגון הדרגתי של נגני YouTube ועל טעינה עצלה. סרטוני MP4/M4V/WebM מנוגנים ב-`<video>`; קישורי HLS (`.m3u8`) נבדקים בעזרת נגן תואם; אין להציף מאות נגנים בבת אחת.
5. **תקלות:** לבדוק קישורים וסרטונים שאינם נטענים גם בפרקים קודמים, במיוחד בפרק הראשון; לזהות מקור רשמי חלופי, לשמור את הפריט ולא לדלג עליו. אם עדכון GitHub/Vercel נכשל — לבדוק ולנסות לתקן באותה ריצה בלי לולאות אינסופיות.
6. **פריסה:** העבודה נמצאת ב-`barkinam21-pixel/cosmos-to-life` בענף `main`, Vercel מעדכן Production באופן אוטומטי. לבדוק READY אחרי שינוי. אין תלות ב-TinyFish, אין צורך בקוד מצד הצופה.


## דיבוב חינמי בתוך האתר (בדיקת תאימות אוטומטית, 11.10.2026)
- `dub-free.html` ו־`dub-free.js`: מסלול אופציונלי במחשב עם Chrome תומך, לזיהוי שמע מלשונית נבחרת (`SpeechRecognition.start(audioTrack)`), תרגום אנגלית→עברית ב־Chrome Translator (מודל מובנה), והקראה בקול עברי *קבוע* שנבחר פעם אחת.
- אין שימוש במפתח Gemini, ואין בקוד מגבלת עשר או חמש־עשרה דקות. עם זאת, זמינות ומגבלות צד ספק הזיהוי אינן מובטחות. שמע עשוי להישלח לספק הדפדפן, בעוד שתרגום הטקסט נעשה במכשיר. ייתכן צורך בהורדה ראשונה של חבילת שפה.
- נעשה שימוש במסנן הרקע הקיים ב־`dub-worklet.js` (ללא שינוי בקובץ), בעוצמת רקע התחלתית נמוכה, ואפשרות להשתיק רקע. זה אינו בידוד מקצועי, וייתכן דיבור אנגלי חלש.
- המסלול מבודד לחלוטין מ־`dub.js` ו־`dub.html` למעט קישור גישה חדש, כך שמפתח Google Live, הגדרת הקול והניגון הקיימים אינם נדרסים.
- מסלול החיסכון באנרגיה (`dub-free-ambience-worklet.js`) מסנן חלק מהדיבור האנגלי אך אינו מייצר כלל חבילות PCM שמיועדות ל-Gemini. לאחר לחיצה על ״רק עברית״ מנותק מקור השמע מהמסנן; השיתוף לזיהוי נשאר פעיל. הזיהוי מנסה להתחדש אחרי שתיקות ארוכות, אבל עוצר כשיש סדרת כשלי שירות קצרים. גם לקריין הקבוע יש Watchdog כדי שלא ייתקע במצב ״מדבר״ לנצח.
- בדיקות אוטומטיות ב־`tests/dub-free.test.cjs` ו־`tests/dub-free-sound.test.cjs`. בדיקות רשת/האזנה אמיתית בדפדפן של המשתמש לא בוצעו; **אין להציג את המסלול החדש כמוכח על כל מחשב**.

## מה נותר לבדיקה
- בדיקת הפעלה אמיתית **בדפדפן** לכל המקורות שאינם YouTube, במיוחד PBS, Vimeo וקבצים ישירים מ-NASA, NOAA ו-HHMI. הספירה והבדיקות הסטטיות של קישורים **אינן** הוכחה שהקובץ באמת מתנגן.
- פריטים שהנגן שלהם נחסם או שהקובץ אינו קיים צריכים חלופה מאומתת בתוך האתר, מבלי לדלג עליהם או ליצור סרטון פיקטיבי.
- להמשיך להרחיב באופן איכותי את המקומות שבהם חסר גשר מושגי, כגון אנרגיה, חומר ביקום הקדום, התפתחות אטומים, כימיה, והמעבר מחומר לחיים.
- לפני סיום כל ריצה: לוודא שכל מזהי YouTube רשומים פעם אחת ב-`EMBED_ORDER` ושהפריסה האחרונה READY.

## מבנה טכני
- `index.html`, `life.html`: נתוני `chapters`, רינדור הסרטונים וניווט, המשך אוטומטי, fallback.
- `api/resolve-media.js`: ניסיון לזהות מדיה ישירה ושידורי HLS מתוך דפי מקור רשמיים נבחרים, עם אפשרות לנגן המקורי של PBS.

## חלוקה חסכונית בדפים — הוראת תחזוקה קבועה
- בכל חלק מוצגות **עד 6 יחידות בכל דף פנימי** בעזרת `learning-pages.js`, עם `?page=N` לקישור ישיר, מעבר הקודם/הבא, שמירת מיקום פרק ו־Auto-Next שחוצה דפים. לא נטענים מאות נגנים באותו מסמך במקביל.
- מעברי דפים מתבצעים **באותה לשונית וללא רענון** כדי למזער הפסקה של שיתוף שמע לדיבוב. אין לשנות את `dub.html`, `dub.js`, `dub-worklet.js` או את קישור 🎧 בעקבות פיצול יחידות. במעבר בין חלק א׳ לב׳ עדיין מתקיימת ניווט רגיל.
- כל הוספת סרטונים עתידית חייבת לכבד את מגבלת שש היחידות; הוספה למערך `chapters` ממוקמת אוטומטית בדפים. שמרו `EMBED_ORDER` מלא, תקין וייחודי, וודאו ש־YouTube/Vimeo/HLS משתחררים ממסך קודם.
- היעד הוא **הפחתת צריכת RAM לקראת 1GB לכל דף**; זה איננו גבול מובטח, כי הזיכרון בפועל תלוי בדפדפן, בהרחבות, באיכות הניגון ובמספר הטאבים. בדיקת RAM ודיבוב אמיתית דורשת דפדפן מקומי ומפתח שהמשתמש שומר לעצמו.
